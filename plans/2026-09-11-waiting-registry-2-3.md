## Глобальные ограничения

Действуют в КАЖДОЙ задаче. Значения — дословно из спеки и из машины.

### Форма пробы — читать до первой заведённой строки

🔴 **`probe` отвечает на вопрос «источник ответил» и ОБЯЗАНА выходить нулём.
Фильтрация уезжает из команды в `ripe_match`.** Мастер-спека,
`specs/2026-09-08-waiting-registry.md:170`. Машина это исполняет буквально:
`probe_one` (`scripts/waiting.py:795`) на любом ненулевом коде возвращает
`unreachable`, а не `silent`.

**Это главное, чего нет в хендоффе, и оно переписывает 23 готовые команды.**
Команда вида `grep -c … ` возвращает 1 при нуле совпадений — то есть ЧЕСТНОЕ
молчание приедет как «недостижима». Ровно та ложь, против которой написана вся
преамбула отложки, только с другой стороны.

Разбор одной команды на поля — механически:

| в теле пункта | куда едет |
|---|---|
| `cd ~/dev/mprz` первой строкой | `cwd: ~/dev/mprz` — и из пробы ИСЧЕЗАЕТ |
| `ssh mprz '…'` обёрткой | `host: mprz`, содержимое кавычек — в `probe` |
| `ssh -p 30022 …` с нестандартным портом | см. Задачу 5 (псевдоним в `~/.ssh/config`) |
| грепы и фильтры на хвосте конвейера | `ripe_match`, если их дело — решать «наступило ли» |
| «Сработало, когда вернёт больше 12» | `ripe_match: "^(1[3-9]\|[2-9][0-9]\|[0-9]{3,})$"` |
| «Сработало, когда …» прозой | `ripe_when` дословно |

**Правило выбора команды:** если ненулевой код означает ЗАКОННОЕ молчание —
переписать через `find`, `ls`, `awk`, `cat`, `journalctl`, которые выходят нулём
и при пустом выводе. Если ненулевой код означает настоящую поломку источника —
оставить как есть, `unreachable` тут честен.

### Сторож конъюнкции (`scripts/waiting.py:352`)

Отвергаются `&&`, `||`, `;` и **две команды в столбик** — вне кавычек и вне тела
heredoc. Кавычки и heredoc считаются ДАННЫМИ и не смотрятся: `ssh mprz 'cd x &&
y'` проходит, `cd x` + `y` двумя строками — нет. Неразобранный вход (незакрытая
кавычка) отвергается тоже, нарочно.

### Остальное

- **`title` — в кавычках.** Двоеточие с пробелом в плоском скаляре YAML ломает
  разбор; у заголовков отложки двоеточия частые.
- **`DAYS_WITH_PROBE = 30`, `DAYS_NO_PROBE = 7`** (`scripts/waiting.py:59`).
  Строка без пробы со сроком больше 7 дней — брак формы. Инвариант 5 не смягчать.
- **`waiting.py new` берёт ящик из ТЕКУЩЕГО каталога** (`repo_box()`). Заводить
  строку надо из каталога её репозитория; `--global` кладёт в `~/.claude/waiting/`.
- **Поля при `probe: none`:** `host`, `cwd`, `ripe_match`, `sample` обязаны быть
  явным `none`; `ripe_when` обязателен.
- 🔴 **Ворктри НЕ заводить.** В `~/.claude` ворктри не изолирует, а ОТКЛЮЧАЕТ:
  скиллы, хуки и настройки читаются из живого `~/.claude`.
- 🔴 **`git add -A` не звать.** Только путями: в общем дереве это присвоение.
- 🔴 **`ОТЛОЖКА.md` не трогать до Задачи 11.** Её правят сестринские сессии
  (коммит `98e4abc` добавил пункты 30 и 31 посреди работы предшественника).
- **Обратные кавычки в `git commit -m` исполняются шеллом** — годится `-F -`.
- **Один прогон стенда ≈ 41 с.** Гонять фоном и НЕ править `scripts/`, пока идёт.
- **Правка общих файлов — read-modify-write по якорю** с проверкой якоря на
  уникальность. Никогда перезапись целиком.
- **Время брать из `date`**, а не из головы: сессия может простоять часы между
  замером и записью.

wt "$WAITING_HOME" doctor

- [ ] **Шаг 3: реализовать `tomb_state()`**

Порог — 25 строк: редирект из §5 занимает 6, запас на правку шапки есть, а
пункт отложки короче 25 строк не бывает (самый короткий живой — 18в, 10 строк;
но он не один, дописка идёт заголовком плюс телом).

```python
TOMB = HOME / "ОТЛОЖКА.md"
TOMB_MAX_LINES = 25
TOMB_ANCHOR = "waiting.py list"


def tomb_state():
    """Надгробие не растёт. Возвращает (текст, ok) по образцу hook_state().

    Дописку в конец выведенного файла не предотвратить: сессия, помнящая
    ОТЛОЖКА.md по своему стартовому контексту, допишет туда молча и уедет.
    Предотвратить нельзя — увидеть можно, и это вся задача сторожа.

    До поставки 2-3 файл живой и длинный, сторож красен, и это штатно: то же
    состояние, что у записи хука до Задачи 5 поставки 2-2.
    """
    try:
        lines = TOMB.read_text(encoding="utf-8").splitlines()
    except FileNotFoundError:
        # Файла нет — это НЕ «всё хорошо»: редирект удалили, и следующая
        # сессия заведёт отложку заново с чистого листа.
        return ("надгробие ПРОПАЛО: ОТЛОЖКА.md удалён, а редирект — то "
                "единственное, чем останавливаются живые сессии", False)
    except OSError as e:
        return (f"надгробие не прочиталось — {e}", False)
    if TOMB_ANCHOR not in "\n".join(lines):
        return (f"надгробие НЕ ПОСТАВЛЕНО: в ОТЛОЖКА.md нет «{TOMB_ANCHOR}» — "
                f"файл всё ещё источник правды", False)
    if len(lines) > TOMB_MAX_LINES:
        return (f"надгробие ВЫРОСЛО: {len(lines)} строк при потолке "
                f"{TOMB_MAX_LINES} — кто-то дописал в выведенный файл", False)
    return (f"надгробие цело: {len(lines)} строк, редирект на месте", True)
```

## Задачи 3–10: перенос по ящикам

Все восемь задач одной формы. **Процедура строки** (ниже) не повторяется в каждой
задаче дословно, но исполняется в каждой полностью; в самих задачах названо
только то, чем ящик отличается.

### Процедура одной строки — исполнять от начала до конца, без пропусков

1. **Прочитать пункт целиком** по диапазону строк из карты Задачи 1. Не по
   заголовку: заголовок врёт чаще тела (шапка файла говорит «Ждёт: 20» при 25
   живых).
2. **Завести файл** из каталога ящика:
   ```bash
   cd ~/dev/<repo>
   python3 ~/.claude/scripts/waiting.py new "<заголовок без номера и эмодзи>"
   ```
   Печатает `заведена: <repo-id>/YYYYMMDD-NN` и путь. `title` скрипт закавычит сам.
3. **Дозаполнить поля** по таблице разбора из «Глобальных ограничений».
   `sample` — реальное наблюдение из тела пункта; нет наблюдения — `pending`.
   🔴 Не сочинять: `sample` без наблюдения есть обещание, а не проверка.
4. **Перенести тело** пункта целиком, вниз файла, под шапкой YAML. Последней
   строкой — происхождение: `ОТЛОЖКА.md, пункт N, заведён <дата из тела>`.
   Подсказку-комментарий из шаблона удалить: строка дооформлена.
5. **Выставить срок веером** (§3): подстраховка, а не датчик. Механически по
   возрасту пункта — чем старше, тем ближе, в пределах 30 дней. `probe: none` →
   ровно +7, `waiting.py stamp <id>` выведет сам.
6. **Проверить форму** — до коммита, поимённо:
   ```bash
   python3 ~/.claude/scripts/waiting.py list 2>&1 | grep -A3 недооформл
   ```
   Ожидается: заведённой строки в группе «недооформленные» НЕТ.
7. **Опросить строку живьём** и записать исход:
   ```bash
   python3 ~/.claude/scripts/waiting.py probe
   ```
   Строка обязана дать `silent`, `fired` либо `unreachable` с названной
   причиной — и НЕ упасть. `unreachable` из-за формы пробы (код 91 «cwd не
   нашёлся», 127 «нечем спросить», «ripe_match не компилируется») — это брак
   переноса, чинить сразу. `unreachable` из-за реально недоступного хоста —
   записать и идти дальше.

**Коммит — один на ящик**, в самом конце задачи, путями:

```bash
cd ~/dev/<repo>
git status --short
git add .claude/waiting
git commit -F - <<'MSG'
реестр не-сейчас-работы: N строк переехали из ~/.claude/ОТЛОЖКА.md

Пункты <номера>. Пробы взяты из тел пунктов, фильтр вынесен в ripe_match:
probe обязана выходить нулём, иначе честное молчание приедет как «недостижима».
Старый файл выводится из обращения поставкой 2-3.
MSG
git status --short
```

🔴 `git status --short` ДО и ПОСЛЕ: в каждом репозитории работают чужие сессии.
Увидев в выводе чужие правки — коммитить только свои пути и записать решением.
