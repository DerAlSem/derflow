# Пересборка derflow: правило / нужда / архив

Дата: 13.09.2026 · полоса C-bootstrap · дизайн одобрен владельцем по секциям
13.09 (основание — живым сообщением: «Либо правило, либо нужда, либо архив»).

## Мотив

Не экономия. Замер `scripts/cacheread-mix.py` (30 дней, 124 287 запросов,
понормированная по каждому запросу проба `tmp/prefix-probe.py`) показал: канон
derflow и скиллов — 5,0% префиксного расхода, а не 24% из панели `/usage`;
самый дорогой движок — `_lane-c.md` (2,1%), а не `_capture.md` (0,10%).
Потолок выгоды ~3,7% — этим пересборку не оправдать.

Несущие основания два, оба не про деньги:

1. **Несвежесть.** Скилл входит в сессию один раз, компакт переприкрепляет тот
   же снимок байт в байт (замер v4.17, 893 транскрипта). Правка движка не
   доезжает до идущих сессий.
2. **Порог на рост.** derflow — журнал в одежде инструкции: ~41 глава, 21 с
   версионной меткой, каждая — рассказ об оплаченном промахе. Уроки хранятся в
   той же форме и в том же месте, что и правила, и канон растёт молча.

## Основание (одобрено)

У урока одна работа — изменить решение под давлением. Если он его меняет, он
обязан быть либо **правилом**, достаточно коротким, чтобы висеть загруженным,
либо **нуждой** — машинной проверкой, срабатывающей в тот самый момент. Ни тем,
ни другим — это **архив**: ценен для разбора, в рантайм не грузится никогда.
**На извлечение не ставим:** архив для человека и сессии-разборщика по прямой
просьбе, никакой рантайм-механизм его не читает.

## 1. Три класса и их носители

**Правило** — короткий императив, всегда загруженный. Форма жёсткая: строка-
триггер («когда X…») + строка-предписание; 2–5 строк; без рассказа, версии и
истории промаха; ссылка `→ archive/<имя>` на происхождение (тело ссылки в
рантайм не едет). Носитель — файлы движков, сжатые до слоя правил.

**Нужда** — скрипт/хук, печатающий измеренный факт в момент решения. Критерий
допуска: (а) срабатывает сама, без воли агента; (б) печатает факт, не мнение;
(в) есть машинный сигнал момента — событие хука, вызов инструмента, старт
сессии. Доказанный класс: `context-meter`, `canon-drift`, `waiting wake`,
openspec-гейты, пять `*-bite.sh`.

**Архив** — глава как есть: рассказ, версия, промах, числа. Живёт в
`skills/derflow/archive/<слаг>.md`, по файлу на урок. Не грузится ничем.

**Несущее следствие: свежесть требует нужды.** Правило по определению может
отставать (сессия живёт на снимке) — в правила допускается только то, что
меняется редко; всё, что обязано быть свежим, обязано быть машинной проверкой.

## 2. Целевая топология

Точки загрузки не меняются: роутер при старте, движок при выборе полосы,
захват в конце полосы. Меняется вес в точках.

```
skills/derflow/
  SKILL.md        роутер, как есть (224 строки)
  _lane-c.md      753 → ~120 строк   бюджет 120
  _gates.md       628 → ~100         бюджет 100
  _capture.md    1265 → ~120         бюджет 120 (глава расщепления — главный донор архива)
  _ship.md        228 → ~80          бюджет 80
  _parallel.md    221 → ~80          бюджет 80
  CHANGELOG.md    уезжает в archive/ целиком, файл исчезает
  archive/        по файлу на урок; loader скиллов его не видит (владелец: не в docs/)
```

Имена движков и прогрессивная загрузка сохраняются: их знают `SKILL.md`,
глобальный `CLAUDE.md` и `canon-drift`. Порядок глав внутри движков держится,
чтобы диффы миграции читались как сжатие, а не переезд. Машинные проверки —
в `scripts/` и `hooks/` + регистрация в `settings.json`, по образцу
`canon-drift`. Ориентир веса полосы C: ~92 тыс. токенов → 8–10 тыс.
(следствие, не цель).

## 3. Классификация существующих глав

**Дефолт — архив.** Глава доказывает право быть бо́льшим, два экзамена из
основания. Типовой исход — пара «правило + архив» (~30 из ~41 главы);
~5 «уже машинное» (архив со ссылкой на существующий хук); ~5 чистых правил без
истории; 1 новая нужда.

**Новых нужд — две** (решение владельца 13.09):

1. **Reap-гейт полосы C** на счётчике `openspec list --json`
   (completedTasks/totalTasks) — хук конца полосы печатает «заявка X: 9/28»
   вместо прозы.
2. **Гейт второго круга критики** — расширение существующего
   `openspec-critique-record.sh`: при попытке открыть круг по заявке с уже
   стоящей отметкой — красная строка «круг был, дата, слой закрыт» ДО траты
   ~460k. Таблица отговорок из `_lane-c.md` при этом уезжает в архив целиком:
   её работу делает машинный отказ.

Больше не строим (YAGNI).

### Критик-слой (решения владельца 13.09)

- **Круг положен только заявке, трогающей деньги, права или ПД** — один узкий
  круг, пара критиков, засеян `check.py`. Остальным заявкам — только механика
  (вход `check.py`, после сведения дифф имён сценариев и N → SHALL).
  Основание: критик — единственный слой, видящий дыры замысла (свип их не
  видит по построению), но 460k платят лишь там, где дефект замысла дороже
  круга. Качество модели кодинга этот класс не закрывает: дыра замысла лежит
  до кода.
- **Свипу критик-слой не положен.** Свип — механика «текст против кода»
  (8 из 8 против 0 из 8 у семи кругов); справочник `_conformance-sweep.md`
  грузится только в момент свипа и в эту пересборку не входит.

**Артефакт одобрения — таблица классификации** (глава → класс → носитель →
имя в архиве), по движку за раз; владелец спорит по строкам таблицы, а не по
сорока обсуждениям. Переписанные движки идут диффами поверх одобренной таблицы.

## 4. Порог на рост: переписанный захват

Порядок захвата в конце полосы: урок сначала пишется в `archive/<слаг>.md`
(бывшая глава, форма не меняется, дата в теле). Затем экзамены: сжался до 2–5
строк — строки в слой правил движка со ссылкой на архив; есть машинный сигнал —
пишется проверка. Провалил оба — остался архивом, штатный исход. Версии v4.x
умирают вместе с `CHANGELOG.md`; хронология — имя файла и дата.

**Порог машинный, не дисциплинарный.** Бюджеты движков (таблица в §2) сторожат
два носителя с разными жестами (механика проверена по коду: старт сессии — это
`waiting.py wake`, а `doctor` — нарочно команда для человека): красная строка о
пробитом бюджете печатается **на старте сессии** рядом с дельтой реестра, и её
же дублирует `waiting.py doctor` для ручной проверки здоровья — тем же жестом,
каким он краснеет на дописку в `ОТЛОЖКА.md`. Точное место строки — решение
плана работ. Добавить правило в полный движок можно, только оплатив сжатием
или слиянием существующих — либо урок остаётся архивом.

**Память — третье подтверждение модели, не особый случай.** Она уже устроена
как «правило + архив»: строка индекса ≤120 знаков — правило, тело — архив,
`supersedes` — вытеснение. Добавляется недостающий порог: **бюджет индекса
`MEMORY.md` — 16 КБ**, сторожится той же красной строкой. Смысл порога — зазор:
наша граница срабатывает громко до того, как потолок загрузки харнесса (~24 КБ)
обрежет индекс молча. Строка памяти `memory-delivery-on-touch-untested`
закрывается этим порогом: «распух» становится красной строкой, не ощущением.

## 5. Свежесть: что лечим, что нет

1. Всё, что обязано быть свежим, — не в снимке: нужды исполняются с диска и
   несвежими не бывают. Главное лечение — сокращать долю знания, которому
   вообще нужна доставка.
2. Маленький снимок дёшев в переиздании: перечитка слоя правил ~1,5 тыс.
   токенов вместо 22 тыс. — несвежесть остаётся возможной, но перестаёт быть
   дорогой в исправлении.
3. Дрейф наблюдаем: `canon-drift` печатает расхождение; в слое правил любое
   расхождение — изменение правила, ложных тревог нет.

**Честный отказ:** правило может отставать, принимаем. Доставку по касанию не
строим, пуш в идущие сессии не строим. Правило, которое меняется часто, не
дозрело — ему место в архиве или хуке.

## 6. Очередь применений и охват

| подсистема | что делать | объём |
|---|---|---|
| Канон полос | миграция по §2–4 | вся работа |
| Захват | переписать протокол (§4) — часть канона | входит туда же |
| Хуки | +reap-гейт, +гейт второго круга; бюджеты движков и индекса — строка на старте сессии + дубль в `doctor` | ~день |
| Память | порог 16 КБ в сторожа | строки кода |
| Реестр отложки | эталон «нужды» — не трогаем | 0 |
| Роутер | уже правилообразный — не трогаем | 0 |

**Порядок:** сторожа первыми (миграция идёт под их присмотром), затем движки
от дорогого к дешёвому: `_lane-c` → `_gates` → `_capture` → `_ship` →
`_parallel`. Каждый движок — отдельный коммит со своей таблицей классификации;
откат гранулярный.

**Вне охвата:** механика расщепления (`hand.sh`, транспорт хендоффов) — меняется
только форма её канона; `waiting.py`; доставка по касанию; двухмашинный контур
и MLX.

**Критерий готовности:** пять движков ≤ бюджетов и `doctor` зелёный; каждая
строка правил ссылается на архив или хук; `CHANGELOG.md` не существует; полоса
C грузит ≤10 тыс. токенов канона — проверяется прогоном `cacheread-mix.py`
через неделю жизни.

## Риски

- Классификация субъективна, соблазн раздуть «правила» — держат бюджеты
  `doctor` и таблица на одобрении владельца.
- Сжатие главы может потерять различающую деталь — правило обязано ссылаться
  на архив, деталь остаётся в одном grep от читателя-человека.
- Параллельные сессии правят `~/.claude` — read-modify-write по якорю, коммиты
  мелкие, пуш сразу (канон дома действует и на миграцию канона).
