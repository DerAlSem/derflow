# Выкатка как функция дерева

**Статус:** дизайн принят 08.09.2026. Подпроект 1b; реестр не-сейчас-работы —
отдельная спека, идёт следующей.

## Задача

Гейт выката привязан к намерению сессии, а не к состоянию дерева. Сессия гонит
гейт, потому что **она** решила катить; что соседняя сессия десять минут назад
проверила ровно этот `sha`, она не знает и знать не может — общего состояния нет.

Три следствия, наблюдаемые в работе:

1. **Двойной прогон.** Две сессии на одном стволе гоняют один и тот же гейт по
   разу каждая, на неизменившемся коде. Платится ежедневно.
2. **«Сестринская сессия утащила моё на прод».** Сессия узнаёт, что её код уже
   выкачен, постфактум. Это не сбой — это и есть одна точка интеграции; плохо
   то, что до нажатия не видно, что везётся и чьё.
3. **Одновременная выкатка** запрещена только текстом `_ship.md` («одна точка
   интеграции, не две»). Правило без механизма — то, что по замеру корпуса
   держится хуже всего.

## Не задача

- **Очередь выкатки с порядком.** Слот только отказывает и отправляет в ветку
  интеграции. Очередь сделала бы параллельную выкатку удобной — то есть
  закрепила бы ровно то, что запрещает правило.
- **Кэш вердиктов между машинами.** Только локально.
- **Реестр не-сейчас-работы.** Стыкуется пробой `deploy slot status`, живёт в
  своей спеке.

## Инварианты

1. **Вердикт гейта принадлежит дереву, а не сессии.** Ключ — пара
   `(tree_sha, gate_version)`. Дерево то же и гейт тот же → вердикт действует,
   кто бы ни спрашивал.
2. **Зависящее от среды не кэшируется никогда.** Гейт делится надвое явно.
3. **Слот умирает вместе с держателем.** Строка реестра обязана пережить смерть
   сессии, замок обязан умереть вместе с ней — это противоположные требования,
   поэтому слот не строка реестра.
4. **«Нечего катить» — это ответ, а не ошибка.** Выход 0.
5. **Отказ кодом, а не предупреждением.** Где есть тихий промах, сторож обязан
   отказывать кодом.
6. **Грязное дерево не кэшируется.** Гонится всё, причина печатается.

## Объявление таргета — файлом, не прозой

`_ship.md` требует объявлять деплой-таргет в проектном `CLAUDE.md`. Для человека
это верно, но машине нужен контракт: применяем правило «предусловие выката обязан
держать КОД, а не текст». Проза в `CLAUDE.md` остаётся и ссылается на файл.

`<repo>/.claude/deploy.json`:

```json
{
  "target": "gmb-prod",
  "prod_sha": "ssh vds 'cd /srv/gmb && git rev-parse HEAD'",
  "gate_pure": ["pytest -q", "npm run build"],
  "gate_env": ["curl -sf https://gmb.example/health"],
  "gate_version_files": ["scripts/gate.sh", "pytest.ini"],
  "ship": "bash scripts/deploy.sh"
}
```

`gate_version` = хэш содержимого `gate_version_files` плюс текст самих команд.
Меняется гейт — вердикты обесцениваются автоматически, без ручной инвалидации.

## Компоненты

Единственный носитель логики — `~/.claude/scripts/deploy.py`.

### `deploy.py state <repo>`

Читает `prod_sha` командой из `deploy.json`, сравнивает с `HEAD`. Печатает
`git log --oneline <prod>..HEAD` — **что везётся и из каких веток**, до нажатия.
Прод недостижим → `error` и ненулевой выход; молчаливое «нечего катить» при
недостижимом проде запрещено.

### `deploy.py gate <repo>`

- `tree_sha` = `git rev-parse HEAD^{tree}` — дерево, а не коммит: правка
  сообщения коммита не должна обесценивать вердикт.
- Ищет `<repo>/.claude/gate-verdicts/<tree_sha>.<gate_version>.json`.
- Вердикт есть и `pass` → **`gate_pure` не гонится**, печатается «пройден
  сессией N в T».
- Вердикта нет → гонится `gate_pure`, вердикт записывается.
- **`gate_env` гонится всегда**, независимо от вердикта.
- Дерево грязное → вердикт не читается и не пишется, гонится всё, причина
  печатается.

Формат вердикта: `{tree_sha, gate_version, verdict, at, session, host, tail}`.
Поле `session` — идентификатор сессии из окружения, если он доступен, иначе
`host:pid`: вердикт обязан называть автора, но не обязан требовать сессию.

### `deploy.py slot acquire|release|status <target>`

`~/.claude/deploy-slots/<target>.json`: `holder_pid`, `session`, `host`,
`acquired_at`, `heartbeat_at`. Держатель обновляет сердцебиение во время выкатки.
Без сердцебиения дольше 15 минут слот считается протухшим и снимается — **но
факт снятия печатается**: тихое снятие скрыло бы упавшую сессию. Сердцебиение
ведёт сам `ship` фоновым потоком на всё время выкатки: выкатка законно бывает
длиннее TTL, и потолок сторожит смерть держателя, а не длительность работы.

Слот занят → **выход 3** и текст «занято сессией X с T; приземляйся в ветку
интеграции». Не ожидание, не очередь.

### `deploy.py ship <repo>`

1. `state` → `prod == HEAD` → выход 0, «нечего катить, прод на `<sha>`, твоё внутри».
2. Печать того, что везётся, включая чужие коммиты и их ветки.
3. `gate` → `fail` → ненулевой выход.
4. `slot acquire` → занято → выход 3.
5. Команда `ship` из `deploy.json`.
6. `slot release`, перечитать `state`, подтвердить новый `sha`.

## Отказы

| Условие | Поведение |
|---|---|
| `deploy.json` отсутствует | выход ненулевым, таргет не объявлен |
| прод недостижим | `error`, не «нечего катить» |
| слот протух | снимается, факт печатается |
| слот занят живым держателем | выход 3, без ожидания |
| дерево грязное | вердикт не кэшируется, причина печатается |
| `gate_env` упал при живом вердикте | выкатка запрещена — среда важнее кэша |

## Укус — `~/.claude/scripts/deploy-bite.sh`

Сторож проверяется укусом, а не зелёным цветом. Семь укусов:

1. Два `ship` подряд без правок → второй отвечает «нечего катить», `gate_pure`
   не гонится ни разу.
2. Вердикт есть, дерево то же → `gate_pure` пропущен, `gate_env` прогнан.
3. Правка одного байта в коде → вердикт не действует.
4. Правка `gate_version_files` → вердикт не действует.
5. Держатель слота убит `-9` → слот снимается по TTL, факт напечатан.
6. `ship` при взятом живом слоте → код 3, немедленно, без ожидания.
7. Недостижимый прод → `error`, а не «нечего катить».

Укус 1 и 6 — главные: они проверяют два утверждения, ради которых всё строится.

*(Снято подозрение с `roster-gates`: 518 «вызовов» в корпусе — артефакт замера,

**Чисто по дереву — кэшируется:**

- `pytest -m "not integration"` — маркер исключает интеграционные по построению,
  а `tests/conftest.py` вдобавок **запрещает** юнит-тестам `database.async_session`

  Непричастность к среде обеспечена кодом, а не соглашением.
- `vue-tsc -b`.

**Зависит от среды — гонится всегда:**

- `alembic heads` в дереве против головы прода;
- свежесть `node_modules` в ворктри;
- положение дерева на `origin/main`.

**Гейт уже параллелен** (`-n 12`, «и никогда последовательно») — кэш экономит и
время стены, и токены.

## Отношение к `deploy.sh`

`deploy.sh` уже считает `LOCAL_SHA` против `REMOTE_SHA`, отказывает на грязном
дереве и проверяет существование ref. **`deploy.py` его не переписывает, а
оборачивает:** добавляет вердикт, слот и «что везём», а проверки предусловий
остаются там, где стоят.

⚠️ **Не заворачивать прогон гейта в конвейер.** В `CLAUDE.md` проекта записана
ловушка `feedback_pipe_swallows_pytest_rc`: `| tail` глотает код возврата pytest.
Это прямо инвариант «три исхода, а не два» — исход берётся из кода возврата
процесса, а не из его вывода.

## Открытые вопросы

- **Коммитятся ли вердикты** в проект или лежат вне git. Склоняюсь к вне: это
  локальный кэш одной машины, инвариант 2 запрещает делить его между средами.
- **Чтение `sha` прода.** `main` — прод по конвенции, но фактически выкачен тот
  `sha`, который лежит на ВДС, и он законно отстаёт. Читать с машины, а не из
  `origin/main`.
