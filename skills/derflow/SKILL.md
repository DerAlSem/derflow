# derflow — роутер

Одна входная дверь для любой задачи разработки. Классифицируй запрос в **полосу**,
отправь нужному специалисту с нужным количеством процесса. Человек описывает
проблему обычными словами и **не обязан** знать, какого агента звать.

Это жадный слой — только маршрутизация. Правила полосы живут в её движке и
подгружаются после выбора.

## Announce-контракт (ОБЯЗАТЕЛЬНО до любой работы)

Две части. Обе.

> **Lane `<id>` → `<agent/skill>` — потому что `<причина в одном придаточном>`.**
> Затем: прочитать движок полосы (таблица ниже) **до первой правки**.

Полоса без прочитанного движка — не полоса, а угадывание: там лежат все оплаченные
уроки, и объявить верный маршрут, не открыв их, значит наступить на те же грабли с
правильной табличкой на груди.

Составная задача → по строке на часть. **Исключение:** простой вопрос («что делает
X?», «как это работает?») — не работа; просто ответь. Без полосы, без анонса.

## Классификация интента

| Человек на самом деле просит… | Полоса | Маршрут | Движок |
|---|---|---|---|
| «объясни / что делает X» | **— нет полосы** | просто ответь, без церемоний | — |
| переименовать, поправить текст, значение конфига | **A · тривиальное** | сделай + тест. Без специалиста, без openspec | — |
| малое изменение, где ты знаешь ЧТО менять (кривая модалка, забытое поле) | **B · малый фикс** | специалист (см. дисамбигуацию) + лёгкий гейт (тест, либо `/verify` для чисто-визуального) + коммит. Без openspec | `_gates.md` |
| двусмысленное · трогает деньги/авторизацию/биллинг/перс-данные/публичный контракт/миграцию схемы · >полудня · многосессионное | **C · настоящая фича** | полный цикл openspec. Живая спека обновляется | `_lane-c.md` |
| новый проект / «глобальная проекция» | **C-bootstrap** | большой брейншторм + декомпозиция → засеять базовый `openspec/specs`; дальше фичи текут как C | `_lane-c.md` |
| «адаптировать легаси в openspec / нет спеки, а надо менять сшивку X» | **C-adopt** | `adopt-code` — археология → sweep → промоушен: код → descriptive SHALL → нормативный baseline, дальше обычный C | `_lane-c.md` |
| «спека отстала от реальности · куча незакрытых заявок · доки не сходятся с кодом» | **C-drain** | триаж → группировка по capability → sweep → архив/отбраковка. Долг живой спеки, не новая фича | `_lane-c.md` |
| «X сломалось — почему?» (ты ещё НЕ знаешь, что менять) | **Dx · диагностика** | **сначала `openspec/specs/<capability>`**, затем **superpowers:systematic-debugging** (воспроизведи → корневая причина), потом маршрутизируй фикс как A/B/C | `_lane-c.md` |
| «прод горит, чини сейчас» | **F · инцидент** | минимум церемоний. Обходит требование полного цикла C для денег/авторизации | `_ship.md` |
| деплой · миграция · рестарт · рассылка · ротация ключа | **Ops** | ops-гейт. Не полоса авторинга кода | `_ship.md` |
| «задокументируй X · обнови README · синхронизируй доки с кодом» | **Docs** | **documentation-expert**. Доки = источник правды | — |
| «а можно ли вообще X? попробуй» | **Spike** | одноразовая сборка-чтобы-узнать: без гейта, без коммита → даёт **вердикт** → перезаходит как C, либо выбрасывается | — |
| «этот файл не слишком большой / дизайн нормальный?» | **D · консультация** | `system-architect` (структура) или `simplify` (чистка) → вердикт. Ничего не меняет. Принято → A/B/C | — |
| «мы долго строили — проаудируй всё» | **E · аудит** | многомерный ревью-воркфлоу, либо `/code-review ultra` → ранжированные находки → каждая → A/B/C | — |
| «разберись в незнакомом/чужом репо · онбординг · что тут вообще» | **Orient · explore** | `explore-code` — ленивая golden-path трассировка; отдаёт seams+paths в текущую задачу. Фаза, не полоса | — |
| «просветить *весь* свой репо: доки / дебаг / где нехорошие решения» (цель — сам обзор) | **Orient · audit** | `audit-code` — граф+churn+`gap-finder` по топ-N, freshness-персист → C-adopt. **Дорогой: Workflow-фанаут, оценивай токены и ставь потолок** | — |

Диагностика (Dx), консультация/аудит (D/E), фазы Orient и вердикты Spike —
все **перезаходят** как задачи A/B/C.

**«Аудит» — ложный друг; разводи по цели, не по слову.** «Прогони/просвети *весь*
репо» как самоцель (доки, где гнильё) → `audit-code`, и это **whole-repo
Workflow-фанаут по хотспотам, дорогой by design** (один воркер на узел). А «мне надо
**сориентироваться, чтобы впилить фичу** в область X» — **не тот интент**: цель —
изменение, ориентация лишь его разогрев → **scoped `explore-code`** по этому seam'у
(ленивый one-path, без фанаута), дальше правка течёт как B/C. Тянуться к `audit-code`
ради подготовки фичи = потратить аудит всего репо (≈миллионы токенов), чтобы ответить
на вопрос об одной сшивке. (Боевое: «аудит код» для турнирной фичи → 55-воркерный
Workflow ≈ 2.9M токенов, когда просили scoped `explore-code`.)

## Дисамбигуация агентов (выбирай по интенту, не по ключевому слову)

| Ситуация | Бери | НЕ |
|---|---|---|
| Строить / добавлять / менять структуру UI или проводку | `frontend-developer` | make-interfaces (полировка), ui-ux-designer (критика) |
| UI работает, но «ощущается дёшево» — отступы, радиусы, движение | `make-interfaces-feel-better` | frontend-developer |
| «Это правильный флоу / вёрстка / доступно ли?» | `ui-ux-designer` | frontend-developer |
| Форма системы целиком, границы, «это надо разделить», файл слишком большой | `system-architect` | backend-architect |
| Конкретный дизайн API, схема БД, эндпоинт/сервис | `backend-architect` | system-architect |
| Чего НЕ ХВАТАЕТ (пропуски, забытый случай) | `gap-finder` | code-reviewer |
| Понять незнакомый / свежесклонированный репо | `explore-code` | system-architect (он критикует свежую спеку, не код) |
| Просветить СВОЙ репо (доки / дебаг / плохие решения) | `audit-code` | `/code-review` (баги на диффе, не ориентация) |
| Завести baseline openspec ИЗ существующего кода | `adopt-code` | обычный Lane C (он предполагает, что спека уже есть) |
| Менять код там, где спека уже есть | Lane C | `adopt-code` (только когда сшивка неспецирована) |
| Баги/корректность + качество того, что ЕСТЬ, на рабочем диффе | `/code-review` (`ultra` = глубоко) | gap-finder |
| Применить переиспользование/упрощение/чистку (качество, не баги) | `simplify` | /code-review |
| Безопасность ожидающих изменений | `/security-review` | code-reviewer |
| Найти корневую причину бага / неожиданного поведения | `superpowers:systematic-debugging` | code-reviewer |
| Реализовать/оптимизировать именно Python | `python-pro` | frontend-developer |
| Ad-hoc SQL, выборка под миграцию, медленный запрос | `sql-pro` | backend-architect (он проектирует схему, а не пишет запрос) |
| Платёжный шлюз, вебхуки, идемпотентность, возвраты, сверка | `payment-integration` ⚠️ | backend-architect |
| Политика конфиденциальности, оферта, согласия, дисклеймеры | `legal-advisor` ⚠️ | — |
| Точечные доки, README, обновить описание API | `documentation-expert` | copywriting (он продаёт; этот объясняет) |
| Задокументировать **большую существующую систему** — архитектурное руководство, разбор решений | `docs-architect` | documentation-expert (это точечное) |
| Исчерпывающий справочник — все параметры, полная поверхность API/конфига | `reference-builder` | docs-architect (тот повествует, этот каталогизирует) |
| Туториал, онбординг-гайд, пошаговый разбор фичи | `tutorial-engineer` | documentation-expert |
| Сделать русский текст нативным (не калька/канцелярит) | `dertext` | documentation-expert (объясняет), copywriting (продаёт) |

**⚠️ Два агента обещают домен, которого не знают.** `legal-advisor` написан под
GDPR/EU — про 152-ФЗ, ОФД/ФНС и самозанятых там нет ничего. `payment-integration`
написан под Stripe/PCI/мультивалютность — СБП, ККТ и `KkmServer` вне его знания.
Оба годятся как **каркас и чеклист общей дисциплины** (вебхуки, идемпотентность,
возвраты, сверка; структура политики), но любое их утверждение о российском
контуре — догадка. Проверяй по первоисточнику: для платёжного контура работает
внешне-контрактный гейт из `_lane-c.md`, для права — сам закон.

**Дизайн против сборки (перекрытие, которое кусается):** агенты `*-architect`
решают *форму*, когда она неочевидна или нова — схема, поверхность API, границы.
`python-pro` / `frontend-developer` *реализуют*, когда форма уже ясна. Добавить одно
поле или сделать прямолинейный эндпоинт — это **сборка** (`python-pro`), не дизайн;
тянись к `backend-architect`, только когда модель данных или контракт действительно
требуют решения.

Когда подходят двое — бери **более узкого** и скажи почему в строке анонса.

## Движки (читаются после выбора полосы)

| Файл | Что внутри |
|---|---|
| `_lane-c.md` | цикл openspec · reap-гейт и C-drain · спека читается первой · внешние API · критик-слой (`system-architect`/`gap-finder`) |
| `_ship.md` | инцидент F · expedited≠untested · Ops-гейт · параллельная изоляция · ворктри и их жатва · деплой-таргет |
| `_gates.md` | verify-гейт · UI = дизайн · «нет X в UI» может = нет X в модели |
| `_capture.md` | граница проект/контекст · self-learning на выходе · гигиена памяти |

**Всегда, независимо от полосы:** `_gates.md`, если полоса отгружает код;
`_ship.md`, если репо может работаться параллельно (проектный `CLAUDE.md` это
объявляет) — ворктри вырезается **до первой правки**; `_capture.md` в конце.

## Общие ошибки роутинга

- **Пропустить строку анонса** на настоящей работе → маршрутизация становится чёрным ящиком.
- **Объявить полосу и не открыть её движок** — анонс это половина контракта; вторая половина в том, чтобы правила полосы реально попали в контекст.
- **Загонять простой вопрос в полосу** — «объясни X» это ответ без полосы.
- **`audit-code` как разогрев под фичу** — «аудит» в смысле «помоги понять эту область, чтобы её менять» = scoped `explore-code` по seam'у, а НЕ whole-repo аудит (однажды 2.9M токенов). `audit-code` — когда просвет репо и есть цель.
- **Фанаут `audit-code` без оценки токенов** — «топ-N хотспотов» без хардкапа раздувается до 50+ воркеров; оцени «N × ~50k ≈ X» и поставь потолок ДО запуска Workflow, а не считай урон постфактум.
- **Гнать не тот «explore»** — Lane C explore (дизайн по живой спеке) ≠ Orient explore-code (разведка чужого репо); и никогда не гоняй агентов И руками по одним файлам.

## Deliverable evolves

**v3.21.** Уточняй на живых задачах; когда правило маршрутизации оказывается
неверным или появляется полоса, обновляй эти файлы через
**superpowers:writing-skills**. Новые золотые пути захватывает слой
`self-learning` (`_capture.md`).

**История версий — `CHANGELOG.md` рядом.** Там «почему так решили»: каждая запись
это оплаченный боевой промах с ценой. Здесь — только «что истинно сейчас».
Не сливай их обратно: датированная история, живущая в живом документе, — ровно та
ошибка, которую запрещает правило v3.1 (и которой derflow болел до v3.18).
